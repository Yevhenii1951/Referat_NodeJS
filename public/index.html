🏗️ Architektur von Node.js

Wie funktioniert Node.js intern? Einfache Übersicht und Erklärungen.

Ihr JS-Code
Sie schreiben die Geschäftslogik der Anwendung in JavaScript. Das sind die Verarbeitung von Anfragen, das Routing, die Arbeit mit Daten.
Node.js API
Eingebaute Module (fs, http, path, crypto) ermöglichen die Arbeit mit Dateien, Netzwerken, Streams, Verschlüsselung usw. ohne externe Bibliotheken.
Event Loop
Der zentrale Zyklus, der alle Ereignisse und Aufgaben asynchron verarbeitet, ohne den Haupt-Thread zu blockieren. Er macht Node.js schnell und reaktionsfähig.
libuv + C++
Die libuv-Bibliothek in C++ verwaltet asynchronen I/O, Threads, Ereigniswarteschlangen und die Interaktion mit dem OS. Sie verbirgt die Komplexität der Arbeit mit Low-Level-Operationen.
Betriebssystem
Node.js interagiert direkt mit dem OS, um auf das Dateisystem, Netzwerke, Prozesse und Threads zuzugreifen. Das ist die unterste Ebene der Architektur.

🍽️ Analogie: Node.js — der Super-Kellner

Statt vieler Kellner (Threads) ist Node.js ein schneller Kellner, der alle Gäste bedient, ohne zu blockieren und ohne zu ermüden.

🔑 Schlüsselkomponenten der Architektur

🔄

Single Thread

Ein Haupt-Thread führt den JavaScript-Code aus

Erstellt keine neuen Threads für jede Anfrage
📨

Event Queue

Ereigniswarteschlange für asynchrone Operationen

Speichert Aufgaben, die auf Ausführung warten
🛠️

Worker Threads

Separate Threads für rechenintensive Aufgaben

Für CPU-intensive Operationen
🚀

V8 Engine

JIT-Kompilierung, Code-Optimierung

💡 Praxisbeispiel: Blockierender vs. Nicht-blockierender Code

❌ Blockierender Code (schlecht)

// Der Server "hängt" für 2 Sekunden
app.get('/data', (req, res) => {
  // Simulation einer schweren Operation
  const start = Date.now();
  while (Date.now() - start < 2000) {
    // Warten 2 Sekunden
  }
  res.send('Daten geladen');
  // ❌ Alle anderen Nutzer müssen warten!
});
Problem: Blockiert den gesamten Server für 2 Sekunden

✅ Nicht-blockierender Code (gut)

// Der Server arbeitet weiter!
app.get('/data', async (req, res) => {
  // Asynchrone Operation
  const data = await fetchDataFromDB();
  res.send('Daten geladen');
});

async function fetchDataFromDB() {
  return new Promise(resolve => {
    setTimeout(() => {
      resolve('Daten aus der Datenbank');
    }, 2000);
  });
}
// ✅ Andere Anfragen werden sofort bearbeitet!
Vorteil: Der Server bleibt reaktionsfähig

💬 Real-time Mini Chat

🎯 Funktionsweise:
• Senden: POST Request an /api/messages mit Username & Text
• Empfangen: GET Request holt alle Nachrichten aus JSON-Dateи
• Auto-Refresh: Nachrichten werden alle 10 Sekunden обновляются
• Persistenz: Nachrichten werden in messages.json сохраняются

// Nachricht speichern
app.post('/api/messages', (req, res) => {
  const message = {
    username: req.body.username,
    message: req.body.message,
    timestamp: new Date().toLocaleTimeString()
  };
  messages.push(message);
  fs.writeFileSync('messages.json', JSON.stringify(messages));
});

🚀 Probieren Sie es aus: Senden Sie eine Nachricht und sehen Sie in Echtzeit erscheinen!

📝 Datei-Erstellung Demo

🎯 Was passiert beim Erstellen:
• Input-Validierung: Dateiname und Inhalt будут проверены
• Server-Request: POST an /api/write-file mit Daten
• File Creation: Node.js создаст файл с fs.writeFile()
• Erfolg-Mелдung: Vollständiger Pfad der erstellten Datei wird angezeigt

const path = require('path');
const fs = require('fs');

app.post('/api/write-file', (req, res) => {
  const { filename, content } = req.body;
  const filePath = path.join(__dirname, 'created_files', filename);
  
  fs.writeFile(filePath, content, 'utf8', (err) => {
    if (err) return res.json({ success: false, error: err.message });
    res.json({ success: true, path: filePath });
  });
});
